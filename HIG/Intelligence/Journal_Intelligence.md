# Journal Intelligence

Status: architecture documentation from ARCH-TASK-0001.
Source: Headquarters Journal Architecture Handoff v0.1.

## Purpose

Journal Intelligence classifies raw journal, journey, and trade review entries into structured Headquarters knowledge while preserving original source records.

## Responsibilities

- Preserve raw entries through the Archive.
- Classify entries by type.
- Extract repeated lessons.
- Detect repeated mistakes.
- Detect repeated strengths.
- Propose Doctrine Candidates.
- Propose Growth Events.
- Support Commander, Guardian, Historian, Academy, Doctrine, and Archives.

## Non-Responsibilities

- Does not create doctrine automatically.
- Does not rewrite user entries.
- Does not judge the Operator.
- Does not replace the current journal before Shadow Mode.
- Does not implement AI classification in this task.

## Entry Classification Types

- Market Observation
- Personal Reflection
- Mission Reflection
- Emotional State
- Motivation
- Risk Note
- Lesson
- Doctrine Candidate Source
- Growth Event
- Guardian Risk Signal

## Department Relationships

| Department/System | Use of Journal Intelligence |
|---|---|
| Commander | Daily context and strategic reflections. |
| Guardian | Repeated risk patterns. |
| Historian | Similarity search and old lesson retrieval. |
| Academy | Growth events and course triggers. |
| Doctrine Engine | Doctrine candidate queue. |
| Archives | Immutable raw source preservation. |
| Recognition Office | Quiet victories and discipline events. |

## Implementation Timing

Journal Intelligence should be implemented only after Mission Debrief and Archives foundations exist. This document authorizes architecture alignment only.
