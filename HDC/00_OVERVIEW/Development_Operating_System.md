# Development Operating System

## Purpose

The Development Operating System defines the disciplined engineering process used to build Headquarters.

Headquarters is a behavioral institution. Its implementation process must mirror the same discipline that the product expects from the Operator.

## Source-of-Truth Chain

1. HDR — design and institutional doctrine.
2. HTB — technical architecture.
3. HIG — implementation guide.
4. HDC — development behavior and approval control.
5. Code — implementation artifact.

No code may contradict the documents above.

## Mandatory Development Constraints

- One task at a time.
- Each task must fit a 2–4 hour engineering window.
- Codex must stop after each task.
- Codex must summarize changes, tests, and risks.
- No follow-up task may begin without explicit approval.
- Architecture is not invented during coding.
- Every deviation requires an Architecture Change Request.

## Implementation Principle

The goal of the process is not speed. The goal is controlled construction with minimal architectural drift.
